# 余弦相似度投票池设计

## 背景

当前模型投票池的构造方式位于 `server.py`，逻辑为直接截取前 `vote_num_models` 个客户端模型作为投票参考模型。该实现简单，但存在两个问题：

1. 投票模型来源固定，容易引入系统性偏置；
2. 投票池与当前目标客户端没有针对性的相似性筛选，难以保证参考模型与目标客户端任务分布足够接近。

本次修改的目标是：将投票池构造方式改为基于客户端模型参数的余弦相似度选择机制。对于每个目标客户端，基于其当前本地模型，与其余客户端模型计算参数向量余弦相似度，并选取相似度最高的前 `K` 个模型作为投票参考模型。

## 目标

在不破坏现有实验线的前提下，引入一种新的投票池构造策略：

- 保留原有固定截取前 `N` 个客户端模型的策略；
- 新增基于余弦相似度的 `top-k` 投票池策略；
- 通过配置切换策略，以支持旧实验复现和新实验对比。

## 非目标

本次修改不涉及：

- 改写投票伪标签生成逻辑；
- 改写 `q` 的更新公式；
- 改写差分隐私共享模型加噪逻辑；
- 引入基于公共样本输出行为的相似度计算。

## 设计方案

### 1. 新增配置项

在 `ExperimentConfig` 中新增：

- `vote_pool_strategy: Literal["fixed", "cosine_topk"] = "fixed"`

含义：

- `fixed`：保持现有逻辑，直接选择固定数量客户端模型；
- `cosine_topk`：对每个目标客户端，选择余弦相似度最高的前 `vote_num_models` 个客户端模型。

现有 `vote_num_models` 保留，其语义调整为：

- 在 `fixed` 模式下，表示固定选择的模型数量；
- 在 `cosine_topk` 模式下，表示相似度筛选时的 `top-k` 数量。

### 2. 相似度计算对象

相似度基于客户端当前本地模型参数计算。

具体做法：

1. 读取目标客户端的 `local_model.state_dict()`；
2. 将其中所有浮点参数按固定顺序展平并拼接成一维向量；
3. 对其余客户端执行相同操作；
4. 使用余弦相似度计算目标客户端与其他客户端之间的相似度；
5. 按相似度从高到低排序，选取前 `K` 个客户端模型。

注意事项：

- 仅使用浮点参数；
- 跳过非浮点 buffer 或结构不兼容项；
- 采用统一键顺序，保证不同客户端参数向量对齐。

### 3. 投票池构造规则

对每个目标客户端单独构造投票池：

1. 候选集合为“除当前目标客户端外”的所有客户端模型；
2. 若可选客户端数量不足 `vote_num_models`，则取全部可用客户端；
3. 若配置 `share_noisy_vote_models = true`，则投票池中使用客户端的共享加噪模型；
4. 否则使用客户端原始本地模型参数。

### 4. 兼容性要求

- 当 `vote_pool_strategy = "fixed"` 时，现有行为不变；
- 原有配置文件不需要强制修改；
- 旧日志与旧实验结果可继续解释；
- 新策略实验通过新增配置显式开启。

## 代码改动范围

### 主要文件

- `common.py`
  - 增加 `vote_pool_strategy` 配置项。

- `server.py`
  - 抽取投票池构造逻辑；
  - 新增基于余弦相似度的投票池选择函数；
  - 为每个目标客户端构造独立的 vote model 集合。

### 可能涉及

- `main.py`
  - 启动日志中追加 `vote_pool_strategy` 输出，方便区分实验。

- `configs/`
  - 新增至少一份使用 `cosine_topk` 的实验配置。

## 风险与取舍

### 风险 1：计算开销增加

由于每轮需要为客户端之间计算模型参数余弦相似度，投票池构造开销会增加。  
当前客户端数规模为 10，可接受。

### 风险 2：参数相似不等于行为相似

基于参数向量的余弦相似度不能完全等价于模型输出行为相似度，但工程实现最直接，且不需要额外引入公共参考数据。

### 风险 3：日志与实验解释需要同步

如果不在日志中打印 `vote_pool_strategy`，后续难以区分“固定投票池”和“余弦相似度投票池”实验。  
因此建议同步增加实验摘要输出。

## 验证计划

至少验证以下内容：

1. `fixed` 模式与当前行为一致；
2. `cosine_topk` 模式能正常运行；
3. 构造出的投票池不包含目标客户端自身；
4. 当客户端数不足 `top-k` 时能正确回退；
5. 日志中能清晰区分当前投票池策略。

## 推荐实验

建议先在现有主线配置上做一个最小对比：

- `vote_pool_strategy = fixed`
- `vote_pool_strategy = cosine_topk`

其余参数保持一致，主指标继续观察：

- `Client Overall | acc_mean`

## 结论

本次设计通过引入 `vote_pool_strategy` 配置开关，在保持原有固定投票池策略兼容的前提下，新增基于模型参数余弦相似度的 `top-k` 投票池构造方式。该方案改动集中、兼容性好，适合作为现有模型投票算法的可比较增强版本。
