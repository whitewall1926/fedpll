# 关键决策

## 2026-04-17

### 决策

使用“仓库文档 + git 历史”作为科研连续性的事实来源，而不是依赖聊天记忆。

### 原因

- 聊天会话不是可靠的持久化层。
- 仓库中的 commit message 和改动文件本身已经包含高价值历史信息。
- 科研连续性需要可恢复、可检查、能和代码对齐的记录。

### 影响

- 以后新会话开始时，必须先读状态文档，再读最近 git 历史。
- 以后任何有意义的代码或实验改动，都要在同一会话中同步更新文档。

## 2026-04-17

### 决策

将 `vote pseudo label` 视为当前主要研究主线。

### 原因

- 最近提交几乎都围绕 vote 消融、可观测性、结果汇总和批量运行展开。
- 这条线当前有最明确、最值得回答的科学问题。

### 影响

- 后续优先解释 vote 相关实验的收益来源，再决定是否扩展到更广的研究方向。

## 2026-04-17

### 决策

将“本地消歧收益是否能够转化为全局精度收益”作为当前 vote 实验的核心判别标准。

### 原因

- 当前汇总结果显示，`vote pseudo label` 已经明显改善本地消歧指标和客户端测试指标。
- 但当前 `server_test_acc` 最好的仍然是 `vote0`。
- 这说明仅仅观察本地 `disambiguation` 指标不足以判断方法是否真正有效。

### 影响

- 后续解读 vote 实验时，不能只看本地指标，还必须同时看 `server_test_acc`。
- 之后的实验总结应该优先分析“本地收益与全局收益的偏差”。

## 2026-04-17

### 决策

按“个性化联邦学习”而不是“普通联邦学习”来解释当前实验结果。

### 原因

- 用户明确说明当前研究设定是个性化联邦学习。
- 在这个设定下，`client_test_acc_mean` 不是附属指标，而是核心目标之一。
- 如果只盯着 `server test acc`，会误判 `vote pseudo label` 的真实价值。

### 影响

- 后续总结实验时，必须同时汇报客户端侧收益和全局侧收益。
- 对 vote 方法的判断标准应改为：是否改善个性化表现，以及这种改善是否还能兼顾全局模型表现。

## 2026-04-17

### 决策

等当前实验全部跑完后，补充 per-client 轮级指标记录。

### 原因

- 当前多数指标都是 mean/std，容易掩盖客户端之间的显著差异。
- 个性化联邦学习里，客户端异质性本身就是需要重点观察的对象。
- 仅看均值无法判断哪些客户端真正受益、哪些客户端被伤害。

### 影响

- 后续将新增客户端级指标导出，而不仅仅保留全局汇总。
- 需要分别记录 q-vector 消歧指标和个性化测试指标，避免再次混淆两种评价对象。

## 2026-04-19

### 决策

实验批次结束后，开始使用语义化指标名，并新增 per-client 轮级指标 CSV。

### 原因

- 旧字段名里 `global`、`balanced_acc`、`client_test` 等命名容易混淆真实语义。
- 用户需要统计最终 10 轮每个客户端的测试准确率，仅有 mean/std 的 `round_metrics.csv` 不够。
- 个性化联邦学习需要直接观察客户端异质性，不能只保留聚合均值。

### 影响

- 新实验会额外生成 `per_client_round_metrics.csv`。
- 新 `round_metrics.csv` 使用 `mean_client_personalized_test_acc` 等语义化字段。
- `scripts/summarize_vote_results.py` 兼容旧字段，避免历史汇总失效。
- 旧实验如果没有 per-client 轮级日志，无法仅凭 CSV 统计最终 10 轮客户端级指标。
